    01

    Forged Media Detection↗

    Taking harmful media down fast, without ever keeping a copy.

    Detect
    UploadPyTorchSpring BootReview

    A trust and safety platform that detects deepfakes and explicit images, routes them for human review, and tracks takedown deadlines. Raw media is never stored.

    Built with

    • PyTorchdetection model
    • Springdecision engine
    • Reactreview console

    The challenge

    Harmful media needs a fast, auditable path from detection to takedown, without the platform becoming a store of the very content it removes.

    What I did

    • Paired a PyTorch detector with a Spring Boot decision engine.
    • Routed flagged items into review with takedown deadline tracking.
    • Produced signed reports while keeping raw media out of storage.

    The result

    • Auditable decisions
    • Deadline tracking
    • No raw media at rest

    02

    SEOPulse↗

    Turning a website crawl into a ranked list of what to fix.

    Crawl
    ReactSpring BootRedisPostgreSQL

    A full-stack website SEO audit platform. Connect a site, run a crawl, review ranked issues, and download a report.

    Built with

    • Springsecured API
    • Rediscaching
    • JWTauthentication

    The challenge

    An audit is only useful if it is fast to run and clear about priority. Raw crawl data is noise until it becomes a ranked list of issues.

    What I did

    • Designed crawl, audit, and report flows across a React client and a secured Spring Boot API.
    • Used Redis for hot data and PostgreSQL for audit history.

    The result

    • Ranked issues
    • Downloadable reports
    • JWT-secured API

    03

    DevTasks↗

    A task manager built like a production service.

    Ship
    NginxReactSpring BootMongoDB

    A task manager with registration, JWT auth, role-based access, search, filters, and pagination. Packaged with Docker and Nginx.

    The challenge

    Most to-do apps stop at CRUD. The goal was the parts real products need: identity, permissions, and queries that stay fast as data grows.

    What I did

    • Implemented authentication, authorization, and task workflows.
    • Added search, filters, and pagination on MongoDB.
    • Containerized the stack with Docker behind Nginx.

    The result

    • Role-based access
    • Paginated search
    • One-command deploy

    04

    RedisLab↗

    Making Redis behavior observable instead of magical.

    Cache
    StreamsLocksRate limitsCluster

    A Redis internals lab: data structures, streams, locks, rate limits, persistence, and cluster topologies, exercised through Spring Boot.

    The challenge

    Redis is easy to add and hard to reason about. Locks, persistence modes, and clustering only make sense once you watch them fail.

    What I did

    • Built experiments for structures, streams, distributed locks, and rate limiting.
    • Ran persistence and cluster setups in Docker to observe behavior.

    The result

    • Repeatable experiments
    • Cluster topologies
    • Spring Data Redis patterns
